<objective>
Harden `pretool-guard.sh` so the constraint pillar fails CLOSED instead of open: block (exit 2) when `jq` is missing or stdin JSON is malformed, cover every write tool including NotebookEdit's distinct `notebook_path` field, and block Bash write commands aimed at protected paths — all from a single-source protected-path pattern.

Purpose: Today the guard is fail-open. `jq -r '… // empty' 2>/dev/null` yields empty output when jq is absent or JSON is broken, the `case` matches nothing, and the script falls through to `exit 0` (ALLOW). A protected write slips past exactly when the environment is degraded. This plan closes that leak — it is the Walking Skeleton slice every other Phase 1 plan builds on (SKELETON.md).

Output: A rewritten `pretool-guard.sh` and an executable test harness proving each GUARD behavior by exit code.
</objective>

(1) FAIL-CLOSED PREAMBLE (GUARD-01, D-01): first `command -v jq >/dev/null 2>&1` — on failure print a jq-specific cause to stderr (`[guard] jq 미설치 → fail-closed 차단 (jq 설치 후 재시도)`, per D-03) and `exit 2` BEFORE reading stdin; then `input=$(cat)` (read stdin ONCE); then `printf '%s' "$input" | jq empty >/dev/null 2>&1` — on failure print `[guard] JSON 파싱 실패 → fail-closed 차단` and `exit 2`. Use `jq empty` (parse-only, not `jq -e .` which also fails on null/false). (2) SINGLE-SOURCE PATTERN (CONTEXT single-source requirement): define one extended-regex variable `PROTECTED_RE='(\.env($|[./])|application-prod|secret|db/migration/)'` — this replicates the existing glob semantics (matches `.env`, `.env.production`, `application-prod*`, `*secret*`, `db/migration/`) while preserving the `.environment.ts` non-match via the `($|[./])` anchor. Both branches consume this ONE variable via `grep -Eq` — no second definition. (3) BRANCH on `tool=$(printf '%s' "$input" | jq -r '.tool_name // empty')`: for `Bash`, extract `.tool_input.command` and block (exit 2, GUARD-03) ONLY when a **write operator targets a protected path** — NOT on a bare substring match of the whole command (that false-positives on benign reads like `grep -ri secret .`, `git commit -m "rotate secret"`, `git log -- .env.example`, and stderr redirects like `2>/dev/null`, breaking SC#3's benign-allow). Keep `PROTECTED_RE` as the single source; add a SEPARATE, orthogonal write-operator check so the protected pattern must appear as the operator's target. Cover three operator families, each requiring `${PROTECTED_RE}` as the argument/target: (a) redirect/tee — `>`/`>>` or a command-position `tee` whose following path token contains `${PROTECTED_RE}` (anchor so an fd redirect such as `2>/dev/null` whose target is NOT protected does not match); (b) in-place edit — `sed -i` / `perl -i` with `${PROTECTED_RE}` among its args; (c) copy/move — a command-position `cp`/`mv`/`install` (anchored at command start or after a `;`/`&&`/`|` separator, so `npm install pkg-with-secret` is NOT caught) with `${PROTECTED_RE}` as an argument. Match with `grep -Eq` against the command string; on match print `[guard] Bash 쓰기 차단(보호 경로): <cmd>` and `exit 2`. A command with no write operator is ALLOWED even if it mentions a protected keyword. Never `eval`/`sh -c` the command string. For the default case (write tools) extract `p=$(printf '%s' "$input" | jq -r '.tool_input.file_path // .tool_input.notebook_path // empty')` — reading BOTH keys (Pitfall 2) — and if `$p` matches `$PROTECTED_RE`, print `[guard] 보호 파일 수정 차단: <p>` and `exit 2` (GUARD-01/02). Fall through to `exit 0` (allow). Keep all stderr messages Korean to match the existing `[guard]` convention (surgical, per project CLAUDE.md §3). Do NOT `eval`/`sh -c` the command string — treat it as opaque data (RESEARCH §Security V5). Run Task 1's harness → all assertions PASS (GREEN).
