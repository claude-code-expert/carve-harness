## Phase Goal

**As a** harness operator who just upgraded Claude Code, **I want** `/harness-audit` to mechanically PASS/FAIL every Phase 1–2 gate, **so that** I learn the guards still fire from one exit code instead of re-reading prose.

<sub>Derived from ROADMAP Phase 4 Goal (SC1, SC2, SC4). MVP structure: one thin end-to-end slice — a runnable audit that green-lights a correct harness (exit 0) and red-flags a broken one (non-zero) for the mechanical checks. Plan 02 adds the policy-mapping + sentinel checks (AUDIT-03).</sub>

<objective>
Replace the one-line prose `/harness-audit` (`.claude/commands/harness-audit.md:4`) with a real `.claude/hooks/harness-audit.sh` that mechanically asserts the AUDIT-01 and AUDIT-02 conditions and exits non-zero on any failure, 0 when clean.

AUDIT-01 (D-04..D-06): jq present; all 6 hook events registered in `settings.json .hooks`; every `hooks/*.sh` referenced by settings is an existing `+x` file; `bash -n` clean on every `.claude/hooks/*.sh`. AUDIT-02 (D-07, D-08): the PreToolUse matcher equals `Write|Edit|MultiEdit|NotebookEdit|Bash`, and `pretool-guard.sh` carries the Bash-write `tool_input.command` inspection + `PROTECTED_RE` write-operator checks.

The load-bearing design is D-03: the audit reads everything under `AUDIT_ROOT="${CLAUDE_PROJECT_DIR:-$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)}"`, so its test can `cp -r .claude` into a temp dir, mutate the copy, retarget `CLAUDE_PROJECT_DIR`, and prove each break — without ever touching the live harness. Unlike a hook, the audit MAY exit non-zero (it is a report, not a gate).

Output: a new `harness-audit.sh`, a rewritten `harness-audit.md` invoker, and a new `harness-audit.test.sh` proving the positive baseline plus four AUDIT-01/02 negatives.
</objective>

## Trust Boundaries

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-04-02 | Repudiation (false PASS) | The audit reports PASS while a gate is actually broken | mitigate | Each check has a paired negative that must flip the exit code (jq-absent, unregistered, stripped +x, dropped NotebookEdit). A check with no failing negative is not trusted. |
| T-04-03 | DoS (audit crash) | Malformed settings.json makes the audit crash instead of FAILing | mitigate | jq reads guarded; a parse failure counts as a FAIL, not an unhandled error. |
| T-04-SC | Tampering | Supply-chain (package installs) | accept — N/A | No packages; Bash+jq+coreutils only. |

Residual `high` with no mitigation: none.
