## Phase Goal

**As a** harness operator, **I want** the audit to also prove each safety-critical *rule* still has a *gate* enforcing it (and that the handoff is real, not a `[내용없음]` stub), **so that** a policy can't silently drift into unenforced prose.

<sub>Derived from ROADMAP Phase 4 Goal (SC3). MVP structure: extends the runnable audit with the policy→gate + sentinel checks so an orphaned safety rule or a stub handoff turns the audit red. Completes AUDIT-01/02/03.</sub>

<objective>
Add AUDIT-03 to `harness-audit.sh` at the safety-critical scope confirmed in CONTEXT (D-09). Two checks:

1. **Policy→gate mapping (D-10):** for each safety-critical policy, assert its enforcing gate artifact is present under `$AUDIT_ROOT` — protected-path block (`PROTECTED_RE` in pretool-guard.sh), Bash-write block (`tool_input.command`), fail-closed jq preamble, the `permissions.deny` safety entries (`Read(./**/.env*)`, `Bash(rm -rf*)`, `Bash(git push*--force*)`), PII masking (`<masked>` in log-event.sh/lib-protected.sh), and the Stop gate registration. A missing gate → FAIL (orphan policy).
2. **Sentinel-handoff rejection (D-11):** if `$AUDIT_ROOT/specs/HANDOFF.md` exists and contains `[내용없음]` or `자동 수집`, FAIL. Absent HANDOFF.md is not a failure.

Scope guard (D-12): the audit does NOT enumerate `rules/code-convention/*` — those are LLM guidance with no possible hook gate; enumerating them would force fake mappings. The live harness (post Phase 1–3) satisfies every mapped policy and has a real handoff, so the positive baseline stays exit 0 (SC4).

Output: AUDIT-03 checks appended to `harness-audit.sh`, and AUDIT-03 negatives appended to `harness-audit.test.sh` (removed deny-entry, stripped PROTECTED_RE, seeded sentinel handoff, absent-handoff-still-passes).
</objective>
