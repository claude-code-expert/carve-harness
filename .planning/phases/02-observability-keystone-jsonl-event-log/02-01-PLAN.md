## Phase Goal

**As a** harness operator, **I want to** see every constraint-guard decision recorded as one structured JSON line in `logs/`, **so that** I can audit what the guard blocked or allowed — without that record ever weakening the fail-closed guard.

<sub>Derived from ROADMAP Phase 2 Goal (outcome-shaped, not a canonical user story). MVP structure: this plan is one end-to-end observability slice — a hook fire produces a real, verifiable log line.</sub>

<objective>
Build the keystone: a single-source, best-effort JSONL append helper, and wire it into the first hook (pretool-guard) so a guard decision produces exactly one structured log line — while proving the log call can NEVER change the guard's exit code. This is the load-bearing correctness slice of Phase 2; every later plan reuses this helper.

Purpose: OBS-01 needs a zero-dependency structured event trail (the keystone Phase 4 `/harness-audit` will consume). The entire technical risk concentrates in three failure modes: (a) breaking/forging JSON by concatenating attacker-controlled paths — solved by `jq -cn --arg`; (b) changing a hook's exit code when logging fails, reintroducing the exact fail-open Phase 1 killed — solved by subprocess isolation + literal exits (D-05); (c) leaking secrets/PII — solved by PROTECTED_RE masking of file paths and by NOT logging raw Bash commands.

Output: `.claude/hooks/log-event.sh` (helper), `.claude/hooks/lib-protected.sh` (single-source PROTECTED_RE), edited `pretool-guard.sh` (sources lib-protected, logs at all four exit points), new `.gitignore` (logs/), and an executable test proving append-count, JSON validity, masking, and exit-code preservation.
</objective>

  bash log-event.sh <event> <tool> <decision> [target] [reason]
    event    = hook name: PreToolUse | PostToolUse | Stop | SessionStart | PreCompact
    tool     = tool name when present (Write/Edit/MultiEdit/NotebookEdit/Bash), else ""
    decision = allow | block | format-ok | format-fail | format-skip | pass | fail | loop-yield | start | save

    reason   = optional (missing | error) — used by OBS-02 in Plan 02
  Emits exactly one line to $DIR/logs/$(date -u +%F).jsonl and ALWAYS exits 0 (best-effort).

Event line schema (one compact JSON object per line):
  {"ts":"<ISO8601 UTC>","event":"...","tool":"...","decision":"...","target":"...","reason":"..."}
  ts via `date -u +%Y-%m-%dT%H:%M:%SZ`. target/reason keys OMITTED when their value is "".

Project-root + daily-file resolution (RESEARCH §Pattern 4):
  DIR="${CLAUDE_PROJECT_DIR:-$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)}"
  LOG="$DIR/logs/$(date -u +%F).jsonl"

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Claude PreToolUse event → pretool-guard.sh stdin | Untrusted tool_input (file_path, notebook_path, Bash command) crosses here and becomes a log `target`. |
| pretool-guard.sh → log-event.sh (subprocess) | The security decision (exit 2/0) must be independent of the logging subprocess (D-05). |
| log-event.sh → logs/*.jsonl | Attacker-controlled strings must not break/forge the JSON line, and protected paths must not be logged in clear. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Elevation (bypass) | Logging reintroduces fail-open — a log failure flips the guard's exit code (the #1 threat, D-05) | mitigate | Subprocess helper (isolated: its `exit`/failure cannot reach the parent, which has no `set -e`); every guard exit point calls the helper as a bare command then a LITERAL `exit 2`/`exit 0`. Proven by: `logs` unwritable → guard exit 2/0 unchanged; `env -i PATH=` → guard exit 2. |
| T-02-02 | Tampering / Repudiation | Log injection / forged second line via crafted file path (quote/newline/`{"fake"}`) | mitigate | `jq -cn --arg` binds every field as an auto-escaped string — never concatenation. Proven by: hostile target → line-count delta == 1 and last line parses. |
| T-02-03 | Information Disclosure | Protected path (`.env`, prod config, secret, migration) written in clear to the log | mitigate | Helper masks any `target` matching single-source PROTECTED_RE → `<masked>`; if lib-protected.sh fails to load, target is masked unconditionally (fail-safe). |
| T-02-04 | Information Disclosure | Inline secret VALUE (`sk-…`/`ghp_…`) inside a Bash command logged as target (PROTECTED_RE masks paths, not tokens) | accept (deferred) | Do NOT log the raw Bash command — pass `""` as target for Bash decisions. Full secret-value scanning is GUARD-04 / Phase 5. Residual after mitigation: none in Phase 2 scope. |
| T-02-05 | Tampering | Concurrent-append interleave corrupting a line | accept (ceiling) | Single short line via `>>` (O_APPEND, inode-serialized on local fs) is atomic for one `write()`; `flock` deferred to Phase 5 (NFS / >4096B lines only). Documented ceiling, not unmodeled. |
| T-02-06 | Repudiation | jq-absent block leaves no log line | accept | The security decision (exit 2) is preserved; a jq-less box cannot run the jq-based logger. Documented gap (Pitfall 3). |
| T-02-SC | Tampering | Supply-chain (package installs) | accept — N/A | No packages installed; Bash + jq + coreutils only (SC3). |

Residual `high` with no mitigation: none.
</threat_model>
