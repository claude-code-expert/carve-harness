## Phase Goal

**As a** harness operator, **I want** hardcoded secrets blocked at write time and Stop verification scoped to what I changed, **so that** the last two enforcement leaks (secret content, full-build cost) close without slowing every turn.

<sub>Derived from ROADMAP Phase 5 Goal (SC1, SC2). MVP structure: two thin end-to-end slices — a secret-bearing write is blocked, and an unrelated Stop skips the untouched build — each proven by a test.</sub>

<objective>
Add GUARD-04 (content secret scan) and GATE-03 (incremental verify), the two additive enforcement capabilities.

GUARD-04: define `SECRETS_RE` once in `lib-protected.sh` (mirroring `PROTECTED_RE`), and in `pretool-guard.sh` extract the write content (`.tool_input.content` / `.new_string` / `.new_source` / `.edits[].new_string`) and block exit 2 on a match — after the existing path check, on the write-tool branch only. Benign content must pass (SC1 — patterns are length-anchored to avoid false positives).

GATE-03: in `stop-verify.sh`, gate each stack verify behind a `git status --porcelain` change check — gradle runs only if a `.java|.kt|.gradle` file changed, node only if a `.ts|.tsx|package.json` changed. No matching change → skip (SC2). The load-bearing constraint is D-06: preserve `set -o pipefail`, the GATE-01 loop-guard, the jq-absent skip, the `exit 2` on failure, and the log calls byte-for-byte; a non-git repo falls back to verifying all stacks.

Output: `SECRETS_RE` in lib-protected.sh, the content scan in pretool-guard.sh, the changed()-gated verifies in stop-verify.sh, and extended tests for both.
</objective>
