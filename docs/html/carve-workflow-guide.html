ABOUTcarve-harness 한눈에

carve-harness는 규칙을 문서로 "권고"하는 대신, 위반이 일어나는 바로 그 순간 훅으로 차단하는 가드레일 하네스입니다. 자동 커밋·시크릿 하드코딩·보호 경로 덮어쓰기·미검증 완료 선언 같은 LLM의 반복 실수를 결정적(deterministic)으로 막습니다. 별도 런타임·빌드가 필요 없고, .claude/ 자산과 Bash 훅만으로 동작합니다.

핵심 동작 한 줄

curl 설치 → 스택 탐지 → (구성요소 선택) → .claude/에 자산 생성
    → 생성된 PreToolUse 훅이 위험 명령·시크릿 쓰기를 exit 2로 결정적 차단

다섯 기능 축

축동작
제약보호 경로(.env·prod·마이그레이션)·하드코딩 시크릿·위험 git 쓰기를 PreToolUse 훅이 차단. jq 부재·JSON 파손 시 fail-closed.
피드백PostToolUse가 포맷·린트 후처리, Stop 훅이 빌드·타입·린트·테스트 실패 시 완료 선언 차단 — 변경된 스택만 증분 검증.
상태세션 종료·압축 시 핸드오프 자동 저장(실제 TODO·결정 수집), 시작 시 복원.
관측모든 훅 판정을 logs/*.jsonl에 기록(PII 마스킹), 리포트·회전. 세션 시작 배너가 로드된 전 구성을 표시, 훅 메시지는 [carve-harness:<hook>] 프리픽스로 통일.
자가감사/harness-audit — 42개 기계 체크로 하네스 오구성을 PASS/FAIL 판정.
이 문서의 위상

이 가이드는 carve-harness v0.0.12 전체 개요입니다. 3기둥 모델부터 구성 인벤토리(훅 9 · 커맨드 14 · 에이전트 20 · 스킬 25 · 규칙 18 · 워크플로 1) · 설치/프루닝 · 오케스트레이션 · 크로스 에이전트까지, 실제 리포에 존재하는 자산만 근거로 다룹니다. 단일 출처는 README.md · CHANGELOG.md · docs/md/orchestration.md입니다.

PART 13기둥 모델

하네스는 세 개의 기둥으로 서 있습니다 — 제약(막는다) · 피드백(검증한다) · 상태(잇는다). 여기에 관측과 자가감사가 각 기둥이 실제로 작동하는지를 증명합니다. 각 기둥은 "말"이 아니라 훅으로 강제됩니다.

기둥하는 일구현 (훅 / 파일)
제약 위험 명령·시크릿·보호 경로 쓰기를 쓰기 시점에 차단 pretool-guard.sh (PreToolUse, exit 2) + CLAUDE.md · AGENTS.md · .claude/rules/*
피드백 포맷·린트 자동 후처리 + 빌드·타입·린트·테스트 실패 시 완료 차단 posttool-format.sh (PostToolUse) + stop-verify.sh (Stop, exit 2, 증분)
상태 진행상황·결정·TODO를 저장하고 다음 세션에 복원 session-handoff.sh (SessionStart / PreCompact / SessionEnd)
관측 모든 훅 판정을 JSONL로 남기고 요약·회전 log-event.sh 헬퍼 + logs-report.sh + logs/*.jsonl
자가감사 하네스가 실제로 무장돼 있는지 기계 검증 harness-audit.sh — /harness-audit, 42 체크
fail-closed 원칙

jq가 없거나 훅에 전달된 JSON이 파손되면 쓰기 경로는 무조건 차단합니다(GUARD-01 / D-01). 게이트를 조용히 통과시키느니 막고 보고하는 쪽을 택합니다 — "판단 불가"는 "허용"이 아닙니다.

v0.0.12 신규
  • 프로젝트 맞춤 구축 — /carve-harness-create가 스택(Java/Spring · TS/React/Next · Python/FastAPI · ORM)을 분석해 맞지 않는 구성을 install.sh prune으로 정리(코어는 불가침).

PART 3훅 9종 게이트

훅이 하네스의 심장입니다. 9개 스크립트는 세 부류로 나뉩니다 — 이벤트 게이트 4(6개 이벤트 슬롯) · 공유 헬퍼 2 · 수동 CLI 3. 차단은 exit 2, 허용/후처리는 exit 0입니다.

스크립트트리거역할
pretool-guardPreToolUse보호 경로·시크릿·위험 git 쓰기 차단(exit 2). jq/JSON 이상 시 fail-closed.
posttool-formatPostToolUse확장자로 언어 감지 후 포맷(후처리 전용, exit 0). 매 실행 1건 결과를 JSONL 기록.
stop-verifyStop변경 스택 감지 후 빌드·타입·린트·테스트 게이트. 실패 시 exit 2로 완료 선언 차단.
session-handoffSessionStart · PreCompact · SessionEndstart=핸드오프 복원 + 구성 배너, save=진행상황 저장.
log-event서브프로세스 호출JSONL append 헬퍼 — 스키마·타임스탬프·PII 마스킹 정규식의 단일 출처(D-04).
lib-protectedsource 참조보호 경로 정규식의 유일한 정의(순수 데이터, 부수효과 없음). guard·log-event가 공유.
harness-audit수동 · /harness-audit42 체크 PASS/FAIL, read-only. 실패 항목 있으면 non-zero.
logs-report수동 CLIJSONL 판정 분포·차단 상세 요약 + N일 회전(유일한 쓰기 동작).
eval-java수동 · 스코어러Java/Spring 결정적 품질 확률 P∈[0,1] 산출. LLM 없음 — 같은 입력이면 같은 P.
settings.json은 SKIP이 아니라 병합

기존 프로젝트에 이미 .claude/settings.json이 있으면, 하네스는 그것을 덮지 않고 jq로 훅 6이벤트를 병합합니다 (사용자 permissions·model·자체 훅 보존, 멱등). 이 병합을 건너뛰면 훅이 미등록돼 배너·가드·검증이 전부 조용히 무력화됩니다(v0.0.9에서 고친 근본 버그).

PART 4설치 · 업데이트 · 프루닝

설치

cd /path/to/your-project
curl -fsSL https://raw.githubusercontent.com/claude-code-expert/carve-harness/main/install.sh | bash

설치 시작 시 두 갈래를 묻습니다:

  • [1] 맞춤 구축(권장) — 전체 설치 후 세션에서 /carve-harness-create를 실행하면 스택을 분석해 맞지 않는 규칙·에이전트·스킬을 제안·정리(prune). 정리 전에도 전체 구성으로 동작합니다.
  • [2] 수동 선택 — 항목 단위 체크박스 TUI. ↑↓/jk 이동 · 스페이스 토글 · 1-5 섹션 점프 · a 전체 · 엔터 설치. 기본은 전체 선택.

비대화형은 HARNESS_COMPONENTS=md,hooks bash install.sh. 선택은 .claude/harness-components에 기록돼 update의 신규 파일 필터로 작동합니다.

주변 배선 — 놓치면 안 되는 것

  • settings.json 병합 — 훅 6이벤트 + vtsls(TS·React·JS)·jdtls(Java)·ponytail 플러그인 선언을 jq로 등록(멱등). 서버 바이너리는 별도(install.sh setup이 안내).
  • 오프라인 완결 — jq·shellcheck 정적 바이너리를 vendor/bin에 SHA256 검증과 함께 내장. 인터넷 없이 설치 가능.
  • 설치 끝 /harness-audit 자동 실행 — 42 PASS면 전 게이트 활성.

업데이트 · 롤백 · 프루닝

bash install.sh update    # 신규/변경 자산만 갱신 (선택 구성 필터 존중)
bash install.sh rollback  # 직전 백업( logs/harness-backup/v<버전>/ )으로 복원
bash install.sh prune --keep-list <파일>   # KEEP 밖 비보호 파일 백업 후 제거

prune은 PROTECTED 코어(훅·settings·크로스에이전트 진입·vendor·safety/common 규칙)를 제거 거부하고, 빈 keep-list는 전체 삭제 방지로 차단합니다. 백업은 update와 같은 경로라 rollback이 그대로 복원합니다.

PART 5오케스트레이션 — fable 팀 워크플로

다단계·다모듈 작업은 단일 세션 대신 오케스트레이터 + 워커 구조로 처리합니다. 규칙 정본은 docs/md/orchestration.md, 이를 코드로 고정한 것이 유일한 워크플로 fable-team-pipeline.js입니다. 핵심 원칙: 병목은 코드 생성이 아니라 검증(Verification) — 그래서 생성자와 검증자를 분리합니다.

4-Phase 흐름 (워크플로가 자동 실행)

P1 Spec    fable-researcher 리서치 → 태스크 3~5개 분해(owns·acceptance 필수)
P2 Build   태스크별 fable-builder(worktree) → 완료 즉시 evaluator 검증  [파이프라인]
P3 Document fable-doc-writer + fable-visualizer 병렬  [배리어: 전체 빌드 결과 필요]
P4 Verify  evaluator 최종 SC 판정 → {passed, escalations, finalVerdict}

모델 라우팅 (orchestration.md 1절)

역할모델 · effort담당
오케스트레이터(메인 세션)Fable5 · xhigh작업 분해 · 결과 종합 · 승인 게이트
워커(빌드·테스트·디버깅)sonnet-5 · high구현 · 마이그레이션 · 테스트 작성
읽기 전용 리뷰어sonnet-5 · highlint·테스트·보안 스캔 도구만 허용
포매팅 · 단순 변환haiku · low기계적 작업
옵트인 + 모델 무관

워크플로는 명시해야 실행됩니다 — 발화에 ultracode 키워드, "워크플로우로 돌려줘", 또는 "fable-team-pipeline 실행해줘".

이 프로세스는 모델에 의존하지 않습니다. Fable 5가 아니어도(opus/sonnet) fable-team-guide.md의 SOP(S0~S7)를 수동 실행하면 동일하게 동작합니다. 권위는 도구가 아니라 절차에 있습니다.

PART 6크로스 에이전트

훅 차단은 Claude Code 전용입니다. Cursor · Codex · Aider · Gemini CLI 등 훅이 없는 에이전트를 위해, 규칙의 권위는 강제 수단이 아니라 AGENTS.md 정본 문서에 둡니다. 그리고 어떤 에이전트가 작업했든 .githooks/pre-commit이 커밋 시점에 최종 차단합니다.

문서역할
CLAUDE.mdClaude Code 진입점 — 하네스 전역 가드레일
.claude/CLAUDE.md행동 지침 — LLM 반복 실수 방지 규율
AGENTS.md크로스 에이전트 정본 — 훅 없는 에이전트가 스스로 준수
RULES.md · codex.md · .cursorrules에이전트별 진입 표면 — 같은 규칙을 공유
specs/README.mdSDD 산출물(상태 기둥)의 규약

이 문서들은 같은 규칙을 공유합니다 — 하나를 고치면 나머지도 맞춰야 합니다. Claude Code는 CLAUDE.md로 진입하고, 그 외 에이전트는 AGENTS.md를 정본으로 읽습니다.
